# Project notes: read this before changing the model

The review site and the model code live in this repo, so these notes travel with them. Chat sessions get compacted and new sessions start cold. **These files, not chat memory, are the record of what Henry has decided.**

## Files
- `PROJECT.md`: how the project fits together (coordinates, pipeline, review workflow, standing rules).
- `areas/<area>.md`: one per building or area (area ids match `views.json`). Each has:
  - **LOCKED decisions**: things Henry confirmed or explicitly asked for. Never revert them without asking him. Hand-written.
  - **OPEN questions**: what's waiting on Henry. Hand-written.
  - **Change history**: every change-log item, its approve/rework status, and Henry's pin and per-pin feedback that is still open. Generated by `build_notes.py`. Don't edit by hand.
- `build_notes.py`: regenerates the history sections from views.json and the review sheet export.
- `check_locks.py`: every decision in `model/*.js` carries a comment that mentions Henry. This script lists any such comment that was deleted or reworded since a git ref (default HEAD).

## Rules for every session that touches a building
1. **Before editing**, read `areas/<area>.md` and the `Henry` comments next to the code you are about to change.
2. **Write the decision into the code** as a comment that mentions Henry (e.g. `/* Henry (v8): door in the middle, window either side */`). **Never delete** an old Henry comment when you change that code. If a newer decision replaces it, keep the old comment and add the new one under it (`superseded by v8: ...`).
3. **After the change**, add or adjust the LOCKED line in `areas/<area>.md` if Henry confirmed something new. Put guesses under OPEN, not LOCKED.
4. **Before committing**, run `python3 notes/check_locks.py`. Every lost Henry note has to be intended and explained in the area file.
5. **After pulling reviews**, run `python3 notes/build_notes.py views.json <fb_docs.json> <adm.json>`.
